# CSVマッピングツール（freee会計用）

形式の異なるExcelを集計し、freee会計の収入・支出データとして利用しやすいCSV / Excelを作成するための支援ツールです。

## 概要

freee会計には、ExcelやCSVから収入・支出データを取り込む機能があります。一方で、実際の業務では、店舗・部署・取引先など複数の作成元から、列名・列順・入力形式・シート構成が異なるExcelが集まるケースがあります。

例えば、

- 「日付」「発生日」「取引日」など、同じ意味でも列名が異なる
- 表の前後に、明細ではないタイトル行や注意書きが含まれる
- 1つのシート内に複数の表が配置されている
- 同じ項目が複数列に分かれている
- 日付・金額に、日本語表記、和暦、桁区切り、「円」などの表記差がある
- freeeへ取り込む前に、勘定科目・税区分・税率などを揃える必要がある

といった場合、コピー＆ペーストや列名・形式の統一を手作業で行う必要があります。

この課題に対し、インターネット上の公開情報を調査して自分で要件を整理し、**形式の異なるExcelを解析・集計し、元Excelの列とfreee会計用の項目をマッピングして、取り込み用データを作成するWebアプリ**として開発しました。

例えば、**複数店舗の明細が1つのExcelブックの複数シートに分かれ、合計1,000行を超えるような作業**を利用場面として想定しています。シートごとに列名を書き換えてコピー＆ペーストしたり、日付や金額の表記を1件ずつ揃えたりする代わりに、共通項目への集約と、対応する表記の自動変換・エラー抽出をまとめて行います。

単にCSVを書き出すだけでなく、**「シートごとに異なる項目を揃える」「日付・金額の表記を整える」「修正が必要な行を見つける」作業をまとめて支援する**ことが狙いです。1,000行超は想定する利用例であり、処理速度や削減時間の実測値を示すものではありません。

freee公式ヘルプでも、Excelインポートでは必要項目の準備や、利用する販売管理ソフトによってはExcel上で不要行を削除するなどの事前加工が案内されています。また、freee Developers Communityでも「現在の帳票がfreeeへ直接インポートできない形式の場合、帳票を見ながら転記する作業が必要になる」と説明されています。

## 主な機能

### 1. Excel内の表構造を解析

複数のExcelブック（`.xlsx`ファイル）をまとめてアップロードし、各ブックのシートごとに表ブロックを解析します。**複数ブック・複数シートに加え、1つのシート内にある複数の表も、検出した表ごとに処理して集計結果へまとめます。**

- 罫線で囲まれたセル範囲を利用した表ブロック検出
- 空白行・空白列で囲まれた領域からの表ブロック検出
- 検出した表ブロックの先頭の非空行を見出しとして取得
- 重複した列名の一意化
- 改行・全角空白・不可視文字などを除去した列名比較
- 複数ブックの一括読み込み・集計
- 複数シートの読み込み
- 同一シート内の複数表の読み込み・集計
- 縦表（項目名が左側に並ぶ形式）の転置処理

罫線で表領域を切り出せるレイアウトでは、その領域外のタイトル行・注意書きを、その表の明細に含めずに処理します。

※複数表の検出と、複数段の見出しの解釈は別の機能です。**上下の見出しを結合して列名を作る「複数段ヘッダー」には対応していません。** また、タイトル行・注意書きを、文章の意味から一律に判別して除去する機能ではありません。

### 2. freee会計用項目へのマッピング

**マッピングとは、元Excelの「どの列の値を、freee会計用のどの項目へ入れるか」を対応付ける操作です。** 元Excelの列名を手作業で書き換えるのではなく、画面上で列を選択します。

| 元Excelの列名の例 | 対応付けるfreee会計用の項目 |
|---|---|
| 売上日・取引日 | 発生日 |
| 売上金額・支払金額 | 金額 |

例えば、店舗Aのシートでは「売上日」、店舗Bのシートでは「取引日」となっていても、どちらも「発生日」に対応付けることで、同じ項目として集計できます。

本ツールの必須項目：

- 収支区分
- 発生日
- 勘定科目
- 税区分
- 金額

任意項目として、税計算区分、税額、取引先、取引先コード、備考、品目、部門、決済情報、セグメントなども選択できます。

※税計算区分・税額は、必要に応じて「使用する追加項目を選択」から追加します。ただし、freeeの収入・支出インポートで税計算区分を「外税」にする場合は、税額の入力が必要です（[freee公式ヘルプ](https://support.freee.co.jp/hc/ja/articles/216527163)）。

1つのfreee項目に複数の元列を指定した場合は、空欄を補完しながら1列へまとめます。

### 3. 収入・支出・混在モード

処理対象に応じて、以下を選択できます。

- 収入のみ
- 支出のみ
- 収支混在

収入のみ／支出のみの場合は、収支区分を自動設定します。

※「収支混在」は収入・支出データの混在を指し、縦表と横表の混在とは異なります。

### 4. マッピング設定の保存・再利用

一度設定した列マッピングをJSON形式で保存し、次回以降に再利用できます。

- 設定の保存
- 保存済み設定の読み込み
- 設定JSONのアップロード
- 不要な設定の削除

同じ形式のExcelを繰り返し処理する場合の設定作業を減らすことを目的としています。

### 5. freee用マスタ設定

アプリ内で、処理に利用するマスタを設定できます。

- 勘定科目マスタ
- 税区分
- 税率

勘定科目はCSVから登録できます。

取引先・取引先コードのマスタ設定には対応していません。取引先・取引先コードを扱う場合は、任意項目として選択し、元Excelの列をマッピングします。

### 6. 入力値の正規化・自動変換・エラー表示

集計時に、元Excelから取り込んだ発生日・金額を検証し、対応する表記を自動変換します。

- `2026年9月4日`・`2026-09-04` などを、日付として解釈して `2026/09/04` へ統一
- `令和8年9月4日` など、令和の和暦表記を西暦の日付へ変換
- 金額の桁区切りカンマや「円」を除去し、`1,000円` を数値の `1000` へ変換
- 日付として解釈できない値や、数値化できない金額などの検出
- 不正値がある行の抽出
- エラー行のみの表示
- シート名・対象列・集計結果の行情報を確認できるエラー表示

現在の入力値検証は、集計時の発生日・金額が対象です。freeeの全項目・全取込条件の検証や、画面で編集した後の値の自動再検証には対応していません。

### 7. 検索・フィルタ

集計結果を確認しやすくするため、以下を実装しています。

- 全体キーワード検索
- 列ごとの値フィルタ
- エラー行のみ表示
- 検索条件に応じた編集内容の履歴保存・再入力

### 8. 選択行の一括編集

検索・フィルタ後に対象行を選択し、複数行をまとめて編集できます。

- 収支区分
- 勘定科目
- 税区分
- 税率
- 税計算区分
- その他の選択項目

収入・支出が混在している場合は、収入行と支出行で異なる値を設定することもできます。

### 9. CSV / Excel出力

編集後のデータを以下の形式で出力できます。

- CSV（UTF-8 BOM付き）
- Excel（.xlsx）

## 工夫した点・技術的課題

### 1. 複数表の検出と、タイトル行・注意書きの扱い

シート全体を1つの表として読み込むのではなく、罫線や空白の区切りを手掛かりに、表ごとの範囲を切り出す構成にしました。1つのシート内に複数の表がある場合も、検出した表をそれぞれ処理し、freee用の共通項目へまとめます。

罫線で表領域を分離できる場合は、領域外のタイトル行・注意書きをその表の明細に含めずに扱います。あらかじめExcel上で不要な文字を削除する手間を減らすことを狙っています。ただし、表と同じブロック内に混在する説明文まで、無条件に除去するものではありません。

Excelは利用者ごとにレイアウトが異なりやすいため、固定フォーマットだけを対象とするのではなく、複数の構造に対応できることを意識しました。

### 2. 列名の違いを吸収するマッピング

元Excelとfreee用項目を直接固定せず、画面上で列を対応付ける設計にしました。

また、同じ意味の値が複数列に分かれている場合にも、複数列を1項目へマッピングして空欄を補完できるようにしました。

### 3. 縦表・横表のモード切り替え

一般的な横型の表だけでなく、項目名が左側に並ぶ縦型の帳票についても、転置して処理できるモードを実装しました。

表の向きに応じてモードを切り替えて処理します。**縦表と横表が混在したブックを、自動判別して一度に処理する機能には対応していません。**

### 4. 正規化・バリデーションで取込前の確認を支援

**バリデーションとは、入力値が日付・金額として扱える形式や値になっているかをチェックすることです。** 表記の違いを整える「正規化」と、変換できない値の検出を組み合わせ、**大量の明細から修正が必要な行を見つけやすくし、手作業での表記修正や確認の負担を減らす**ことを狙いました。

列名は比較用に正規化し、取り込んだ発生日・金額は集計時に次の変換・検証を行います。

| 対象 | 入力例・表記差 | 実装した処理 |
|---|---|---|
| 列名 | 前後の空白、全角空白、改行、不可視文字 | 比較用の列名から不要な文字を除去し、空白を統一します。元の表示用列名とは分けて扱います。 |
| 発生日 | 日本語の年月日、ハイフン区切り、令和の和暦表記 | 西暦の `YYYY/MM/DD` 形式へ揃えます。 |
| 金額 | 桁区切りカンマ、「円」付きの数値 | カンマと「円」を除去して数値へ変換します。 |
| 変換できない値 | `2026/02/30`、金額欄の文字列など | 日付・数値の検証でエラー行を記録し、確認対象として表示します。 |

対応する表記は自動で整え、変換できない値は人が確認する構成です。誤った日付や金額の正しい値を推測して書き換えることはしません。

エラー行だけを表示し、シート名・対象列・集計結果の行情報を手掛かりに、確認する箇所を絞り込めます。検索・フィルタ、行選択、一括編集、CSV / Excel出力までを1つの画面フローにまとめ、**freeeへ取り込む前の整形・チェック・確認後の修正を同じアプリ内で支援する**ことを意識しました。

### 5. 設定を再利用できるようにした

同じフォーマットを繰り返し処理するケースを想定し、マッピング設定をJSONとして保存・読み込みできるようにしました。

## 今後の改善点

### 1. 回帰テストの完了

機能追加・修正後の最終版に対して、全テスト項目を再実行し、回帰による不具合がないことを確認したいと考えています。

### 2. コードの分割・保守性向上

現在は主要な処理が1つの `app.py` にまとまっています。

開発を進める中で、Excel解析、入力検証、freee用データ変換、画面表示、エクスポートなどの責務をファイル・モジュール単位で分離した方が、修正時の影響範囲を把握しやすく、テストもしやすいと感じました。

今後は、例えば以下のように分離することを検討しています。

- Excel解析・表検出
- データ変換・マッピング
- 入力値検証
- マスタ・設定管理
- Streamlit UI
- CSV / Excel出力

特にExcel解析部分は、UIから独立した関数・モジュールとして分離することで、画面を起動せずに単体テストできる構成にしたいと考えています。

### 3. テストしやすい設計への改善

機能追加を繰り返したことで、UI処理とデータ処理の結合が強くなった部分があります。

今後は処理の責務を整理し、Excel解析やマッピング処理を独立して検証できる構成にすることで、回帰テストを行いやすい設計へ改善したいと考えています。

## 実行環境・実行方法

### Web版を利用する場合

1. 動作デモのURLを開きます。
2. スリープ画面が表示された場合は **`Yes, get this app back up!`** を押します。
3. 初回はマスタ設定画面から、必要な勘定科目・税区分・税率などを設定します。
4. メイン画面へ移動します。
5. 「収入のみ」「支出のみ」「収支混在」から処理する表の種類を選択します。
6. Excelファイル（`.xlsx`）をアップロードします。
7. 必要に応じてヘッダー探索行数・縦表モードを設定します。
8. 元Excelの列とfreee項目をマッピングします。
9. 「集計実行」を押します。
10. エラー・検索・フィルタを利用して結果を確認します。
11. 必要な行を選択して一括編集します。
12. CSVまたはExcelをダウンロードします。

### ローカルで実行する場合

Python環境で必要なパッケージをインストールした後、Streamlitから起動します。

```bash
pip install -r requirements.txt
streamlit run app.py
```

## 既知の制約・注意事項

- 本ツールは採用活動用のポートフォリオとして開発したものです。
- freee株式会社が提供・保証する公式ツールではありません。
- 対応する入力ファイルはExcel（`.xlsx`）です。
- Excelのレイアウトによっては表を正しく認識できない場合があります。
- ヘッダーや表構造が特殊なファイルでは、手動での確認が必要です。
- 複数段ヘッダー（上下の見出しを結合して1つの列名として解釈する形式）には対応していません。
- 出力したCSV / Excelは、freeeへ取り込む前に内容を確認してください。
- freee側の仕様変更により、必要項目・入力条件などが変わる可能性があります。
- 最終版に対する全90項目の回帰テストは未完了です。
- 本番業務で利用する場合は、十分なテストとバックアップを行ってください。
